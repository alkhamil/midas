# Agent instructions

## Principles

- Canvas is the source of truth; Play derives from the node tree; antd is a structure reference only (variants, props, states, sizes, slots, token names); never replicate antd pixel/DOM.
- Values come from variables (Primitives → Semantic), never copied from elsewhere.
- Hug/fill/fixed sizing is owned by the node; the engine writes it only to fix an axis bound to a variable (`fixBoundAxes`, read through `sizingOf`/`ownSizingOf`: a bound width or height is fixed in every mode, never hug or fill).
- The engine is generic and schema-driven; no per-component code in the engine.
- Strict: no legacy, no migration shims; old files are regenerated.
- Source of truth for decisions is `docs/behavior-spec.md`; it wins over the roadmap.
- Plan: `docs/roadmap.md`.

## Permanent rules

- Not a released product. No backward compatibility, migrations, legacy fallbacks, deprecated aliases, compatibility shims, or "old behavior" branches.
- Delete any function, type, field, or file that does not fit the current plan. No dead code, commented-out code, or unused exports.
- All Behavior data lives under one `behavior` key with a `version` field. Files without `behavior` data open normally, even if they contain components. Files whose `behavior` version/shape mismatches must fail to open with a clear explicit error. Never repair or partially load.
- Templates are data; engine logic stays out of templates.
- Source of truth for decisions is `docs/behavior-spec.md`. Read it before each task. Update its Status section when a stage finishes.
- Workflow per stage: plan briefly, confirm seams, implement with `tdd`, run `code-review`, fix findings, then `handoff`.
- Do only what is asked; no extra features.

## Decisions

- Fase 0 triage (2026-10-31): Button stroke/label/icon-slot/disabled code is done and tested; triage changed no product code.
- Baseline green: builder-core 842 tests, studio 53 tests, 0 failing. Button root owns a stroke bound to `border`; bound strokes never emit inline border props (`outline-color` is the focus ring only); testing.midas regenerates via `scripts/make-testing-file.js`.
- Commit scope (`packages/builder-core/src/commit-scope.js`): a commit skips the component sync and its checks only when every change is a plain layer with whitelisted keys (`PLAIN_KEYS`); an edit whose keys are not known, undo/redo/paste/import, and any master, instance, boolean or flagged layer take the full path.
- Input parity: the wrapper owns all box visuals and interaction states (`focusTarget: "wrapper"`, `:has()` selectors in codegen); the inner control owns text only. No per-component code in the engine.
- Icon choices are remembered per managed slot (generic engine rule: placement carry, retained icon props); the instance Preview panel shows the state select only, no resolved-token list.
- Fixtures are generator-built only: every template master and instance in scripts/fixtures and testing.midas comes from scripts/generated-part.mjs (applyTemplateToFrame, instanceOf). No script writes a template part (a layer marked `part` or `slot`) by hand; the Behavior fixture keeps one deliberate error (the legacy master's missing hover value) that its test asserts.
- Icon slot: an icon slot that starts to show with no icon chosen (its switch turned on, or Input's kind changed to Icon; `newlyShownIconDefaults`) takes the library's first `Icon/<name>` component; one already shown, or holding an icon, is left alone. With no library component it keeps its box, draws nothing, and the Diagnostics show `icon-slot-empty`.
- An icon def's `show` may be `{ prop, is }` (a state gate, e.g. the unchecked side), read everywhere a string show is: canvas, Play, export, panel rows, icon carry and validation.
- Input side slots follow antd: the prefix and the suffix are the only side slots. Each has a switch (`hasPrefix`, `hasSuffix`), a Text|Icon kind (`prefixKind`, `suffixKind`, a segmented enum) and its content: text (hugs) or a swappable managed icon (`prefixIcon`, `suffixIcon`, sized by `iconSize`, coloured by `fg`). Text, icon and kind are remembered per side. Input has no `hasIcon`, `iconPlacement`, `icon` or `iconEnd`; Button keeps `hasIcon` with start or end only, never both. Allow Clear is an icon slot and Show Count a text part, between the value and the suffix. A prop's `visibleIf` may be an `{ all: [...] }`, and an enum may set `control: 'segmented'`.
- Diagnostics `part-missing`: a master lacks a layer its template requires (a non-optional anatomy slot, an affix text slot, or a canvas part; a managed icon slot is an instance layer and never required; a conditional part off at the sample props is an instance layer too). No hidden layers: a conditional part (spinner, shown placeholder, required mark) is made while its condition holds and removed when it fails; the master holds none (`managedPartLayer`, `syncParts`, `no-hidden-layers.test.js`). Auto Fix runs the generator (applyTemplateNodes), adds only the missing layers, removes nothing, and runs in its own undo step.
- Base collections generate from the bundled snapshot (`base-snapshot.json`, built by `scripts/build-base-snapshot.js`), no file picker; base tokens change in Generate base (`buildBasePlan`, `roles.json`, `antd-sizes.json`), then the snapshot is rebuilt. Single-step sizes carry the MD suffix (`controlHeightMD`, `fontSizeMD`, `lineHeightMD`, `borderRadiusMD`, `clearIconSizeMD`); the token JSON is not in the repo, so the snapshot is hand-edited with the same content the builder would emit. The token JSON is expected at `packages/builder-core/src/base-tokens/source/token.json` (or as the script's argument) and the antd source at `D:/antd-ref` (or `ANTD_REF`); the script refuses without both. Only Primitives, Semantic and Typography exist; no Icons or Size.
- Collections are always "<Template> <Name>" (Button Variant, Input Status), never order-dependent, no groups, no group prefix in variable names. A template never writes a default literal: a missing role fails. Auto Fix aliases component variables by schema role, never literals, idempotent.
- Provenance: a component cell aliases Semantic (directly or through its own template's cells). Fixtures build every literal as a Primitive plus a Semantic alias (`scripts/literal-bank.mjs`).
- Gap ladder (`gapXS` 4, `gapSM` 6, `gapMD` 8, `gapLG` 8, `gapXL` 10) replaces margin; `gapXXS`/plain `gap`/32-step `gapXL` are deleted. Button `gap` is per Size mode (xs→`gapXS` … xl→`gapXL`, md role is plain `gap`); Input gap is `gapXS` (4, same value the old `gapXXS` held). Padding ladder is `paddingXS` 8 … `paddingXL` 24 (plain `padding`→`paddingMD`, 32-step `paddingXL` deleted).
- Input has no wave in antd (`components/input` imports none); Input uses the focus halo only.
- Colour literals are hex with alpha (`#rrggbbaa`); the studio reads no `rgba(...)` text. The token importer normalises them (`colorLiteral`), so a rebuilt snapshot stays hex.
- Variant border style (`styles`, e.g. dashed) is applied on a Variant mode change and on instantiate, never on sync, so a hand-set Stroke Dash stays. A user stroke style (Solid, Dash) is the node's own: Play and the export draw it, and the Variant only sets the default on those two events.
- Auto layout alignment has nine positions and the node owns them: Play and the export read the master's `primaryAlign`/`counterAlign` (an instance's own fields win in Play) through `layout.js`; a template's `rootAlign` only seeds a new master.
- Managed slot order: a slot after the label goes before the first layer the anatomy ranks later (the Input's clear before its suffix), else last; one helper, `indexAmongLaterSlots`, serves the editor's plan and the generator. Play and the export follow the schema order, so the canvas must too.
- A root slot is ordered among the root's direct children only: a layer under a container carries its container (`parent`), so container content never moves a root index (the Switch spinner once shifted every later slot, rolling edits back as "wrong position"; the message now carries expected and actual index).
- The icon pass (`applyIconSlotBindings`, `iconBoundKeysOf`) walks managed icon slots only: a managed text layer (Input value, affix texts, count) is bound by `planManagedTextBindings` alone, never by icon tokens (that pass once wrote the icon size onto its w/h and dropped its colour).
- A box of the anatomy (a group frame with display tokens: fill, stroke, radius, size) draws its own border in Play and the export (the group is bound like any layer; `test/helpers/box-template.js` is the engine tests' form-control schema). A persistent state may be an attribute of the root (`statePseudo: "[data-checked]"`, `stateAttributesOf`): the export and Play write it from the prop.
- A managed slot may name a container of the anatomy as `parent` (the checkmark in the box): `planAnatomy` inserts it there with no order of its own, `instanceOf` hangs it under the instance's copy of the container, the studio goes through `managedLayersOf`, and `layerSpecsOf` carries the container as `parentKey` so the master build, sync and part-missing find the slot under its holder. A boolean prop may write the root's `primaryAlign` (on = end, off = start; a Switch's handle), and an enum prop may through its value map (start, center, end): Play and the export carry `data-<prop>-align` from the writer's own map (`alignValueOf`).
- Checkbox (`checkbox`, `isControl`): a `label` root > `box` (a group frame: the one border, fill, radius and size from tokens; the checkmark and the square are built-in glyphs inside it) + a managed `label` (primary slot; text kept in its prop). Checked/Indeterminate are exclusive, Disabled is declared last so it wins. Two dimensions as Button has them: Color (default | primary | danger, a new instance takes primary; every colour token, only the accent follows the mode) and Size (sizes and typography only; Switch's is `small | default`); the model of a template with no fixture is the base plus Auto Fix (`test/helpers/box-template.js` `modelFor`). Registered in the registry only.
- Switch (`switch`, `isControl`): the root is the track (fill, radius, fixed height and width, padding) and the `handle` is a drawn box (an empty group frame the display maps: fill, radius, size); `checked` writes the root's `primaryAlign` (end/start), no text, no border. Size is `small | default` (not the standard five). A container the display maps needs no slot (`drawnBox`).
- Radio (`radio`, standalone; Radio.Group is Tier 3): Checkbox's structure with a round box (`radius-full`, clamped to a circle) and a `dot` glyph; checked recolours the border only.
- The Behavior tab of an instance is drawn for any template: it names no text-colour variable (a template may have no text; that throw blanked Icon Button and Switch), and a preview state the template does not declare is Default (`previewStateOf`); the selector lists the states the template declares.
- An icon def may say `showWhen: <prop>` (a boolean state with a root attribute): its slot is `alwaysVisible` (on the instance from the start, with its role icon) and drawn only while the prop holds; Play marks it `hidden` + `data-show-attr` so a click can show it. Checkbox and Radio glyphs use it.
- A control may declare `toggle: { prop, clears?, once? }` (a boolean state with a root attribute): the root carries `data-toggle` (+ `-clears`, `-once`) and `aria-checked` in Play and the export, and a click in Play runs `applyToggle` (builder-core, over any element-like object: flips the attributes, aria-checked, the alignment of a moving handle and the glyphs that follow a state; a disabled root ignores it). Checkbox clears Indeterminate, Radio only selects, Switch flips. Roles: checkbox, radio, switch.
- Preview states change colour tokens only (a token of kind `color`, any name). Checkbox, Radio and Switch declare hover and focus (border or off-track colour, brand); the export guards them with `:not([data-checked])` while a state with an attribute replaces the same tokens, and the roots carry `tabindex="0"` (`tabIndex` in the JSX). The focus ring is not drawn; the canvas preview recolours the root only.
- Generate Design System is atomic and loud: a template that throws stops the run with its id (`<id>: message`), `generateDesignSystem` cancels the open edit, logs and toasts it; a run the commit backstop (`behaviorProblem`) rolls back shows that reason, never the success summary. The document check treats a managed slot inside a container as part of its instance. `apps/studio/test/helpers/studioReplay.js` runs the real midas.js functions of the path (cut out by name) over a fake document; `designSystemReplay.test.js` guards every template with it.
- No white default: a Design System master frame gets a rest fill only when its template maps a root fill (the token replaces the placeholder), else it is transparent (Checkbox, Radio, FormItem, List); an unchecked Checkbox or Radio box has no fill (`box-bg` is the transparent role), the checked fill is the Color token. Button, Input and Icon Button roots map `bg`, which is white for the outlined look by design.
- Icon-like parts share one definition (`ICON_TOKENS` in icon-slots.js): the Button's start and end icons and its spinner follow `iconSize` and `fg` (`fg-disabled` while disabled) and are bound by one function (`iconSlotBindings`, layers listed by `iconBoundKeysOf`); an arc part's stroke is the CSS `color`. Prefix and suffix icons follow the same tokens. A managed icon slot is drawn with its colour from its class (export and Play, never inline, so a hover rule can win).
- Input clear icon: `clearIconSize` = icon size minus 2 per Size mode, derived in the base data (antd-sizes.json `from`/`offset`, validated by the importer, never a number in the template); colour is the `placeholder` token, hover is `clear-hover` (Semantic colorTextSecondary; play-only "hover has no static canvas visual"), cursor pointer. Value wins over the placeholder: the control's `hidePlaceholderWhenFilled` hides the placeholder part while the value is not empty (canvas partWrites, Play, export); `hideWhenEmpty` hides the value layer while it is empty. The clear layer is added by Allow Clear and removed when off; it is the one present-but-hidden layer (while the value is empty, so Play shows it as the value is typed: `clear-icon.test.js`), rendered conditionally in Play and the export.
- Content slots (a frame instances fill: a component property of type `slot`, `propBind.slot`) are not icon slots (managed layers of a template); never merge them. Their pure decisions live in builder-core (`content-slots.js`, `slot-rules.js`, `slot-property.js`, `slot-diagnostics.js`), not in midas.js. The picker blocks `max` and `onlyPreferred`; every other path only warns: `diagnoseSlots` in the Diagnostics, and a notice from `transaction()` for what an edit newly broke. A template declares content slots as data in `slots` (`SlotDef`, validated by `slotProblems`): the slot `id` is its prop name in the generated code and `accepts` names template ids of the registry and is stored on the slot property with `onlyAccepts`; a candidate's template is its master's `behavior.templateId` (`templateIdsOf`), never an id or a name; `preferred` stays component ids and works only while `onlyAccepts` is off: with it on, the template contract binds and preferred does not widen it. An empty slot is shown only with `showEmpty` (the instance's slot layer is hidden otherwise: `slotVisible`, written where a component property drives visibility); a component put into a slot fills the counter axis once (`slotFillPatch`, always for a horizontal slot); Reset gives a slot back (`releaseSlot`). The export of a template with `slots` is a typed `.tsx` (one slot `children`, several named by slot id, element emitted only when its prop holds something unless `showEmpty`); a template without slots keeps its untyped `.jsx` until Phase 3. Default slot content and repeated children wait for the screen emitter (docs/slots.md). A slot may declare `repeat` (a number prop): Play and the export draw that many copies of its content (`repeatCount`: a whole number of 0 or more, a non-finite value is the prop's schema default), the canvas once; the List template's `item` slot is min 1 and max 1 on purpose; no DOM element gets an id. `TEMPLATES` is the live registry: the built-in templates (`BUILT_IN_TEMPLATES`: Button, Input, FormItem) plus the open document's Custom templates, which live in the document as `behavior: { version, templates }` (schemas are data, ids `custom-<slug>`) and are made the registry by `activateDocumentTemplates` before any node is checked; a malformed one fails to open. A template may have no `icons` list and no `outline`, and `rootLayout` only seeds a new master's direction.
- Template defaults on create: a master is created with its parts at their defaults (a part or affix text a condition shows only for a prop that is off starts hidden), its alignment (`rootPrimaryAlign`, `rootAlign`: Button centre and centre, Input start and centre) and, for the Input only, a fixed 343px width (`rootWidth`, not a variable). The alignment is written once with the auto layout, when a frame is created from or bound to a template; the width is written once at bind time even when the frame already lays out (`bindSizePatch`, shared by the frame and component paths); the node owns both after that and no generator run, Auto Fix or sync puts them back. A Variant's border style (`styles`) is found by the mode's NAME (case-insensitive), never its id: Auto Fix makes ids that are not names. A part on a side (the spinner) is ordered by `sidedPartOrder` on every prop write; the Button's icon placement shows while hasIcon or loading is on (conditions may be `{ any }`). Input Read only is the disabled state turned on by its own prop (`persistentStates.readOnly.as`, `stateOn`): both draw the disabled look and neither can be focused. Managed text (`docs/input-managed-text.md`): an anatomy slot of kind text or control with `managed: true` (optional, with a `shownWhen`) is a layer of an instance only, made and removed by `planAnatomy`/`instanceOf` from its condition (the text stays in its prop), bound at instance level (`planManagedTextBindings`), never required of a master. Input: the master is the placeholder only; value, prefix text, suffix text and count are managed (the count is a slot with `text.counter`). `primarySlot` names each template's primary text part; a managed layer is the label (`labelEntryOf`) only when it is the primary slot. The control's input is always written in Play and the export, from props.
- Anatomy and node fields: a slot of `kind: 'frame'` is a container (a frame marked `behavior.group`) holding the slots that name it as `parent`; the generator, `masterLayersByKey`, part-missing, Play and the export all go inside it, and the studio sync finds layers by descending. A prop may write `layout`, `gap` and `width` of a layer (`NODE_FIELDS`, `nodeFieldPatch`): the canvas gets node fields the instance owns, Play and the export get a data attribute and custom properties on the root (`fieldStyleOf`; Play sets custom properties with `setProperty`, `applyStyle`) read by rules the stylesheet writes. FormItem's label-control gap is the `labelGap` prop alone (no token); its control slot has `fill`.
- Variables window: a file starts with no collection. Create variable makes "Collection 1" + "Mode 1" in the same transaction; nothing else auto-creates one. No Enum variable type.
- Play starts at the top-level frame that holds the selection (a child starts its frame), overriding the flow start marker; with nothing selected, the flow start, then the first frame.
- Size numbers (except line height) follow antd-ref, aliased through Semantic to Primitives steps; colors and the rest come from the token JSON. Intentional exception to "values come from variables".
- Typography is a composite variable type (colour excluded): Primitives hold raw styles, Semantic styles alias them whole per mode, component typography aliases Semantic per Size mode; text parts declare `typography: <role>`; lineHeight is px only.
- Typography editor: the Variables cell opens a floating window (one mode, typed pickers per member, whole-style alias, weight names per family, ratio lineHeight refused). Design panel: attach and detach act on every selected text layer in one undo step each; attached fields are read-only; attach links the style collection to the layer's modes.
- The base `.button` rule keeps its 2px transparent outline (see the focus-outline test); never remove the outline from the base rule.
- Visibility contract: every template declares `parts` (canvas nodes, each with `shownWhen`; `canvas: false` needs a reason) and `playOnly` (each with a reason); static parts are nodes. Browser check: `npm run test:browser --workspace @midas/studio`, then look at `.artifacts/` screenshots before reporting. Open drift: the Play host border shifts children by 1px (canvas stroke is inside the padding); hug text boxes carry 1px slack (hugText), so a label is 1px wider than Play; an empty Input keeps the value's 8px gap, and its placeholder has no Play element.
- Parity gate (browser, `npm run test:browser --workspace @midas/studio`): canvas and Play are measured at 1:1 for every Size and key state. The gate is geometry: every part's box within 0.5px, the root width within 0.1px, and the outline's width, height and centre within 0.5px (`edgeCheck`). The export (JSX and CSS, compiled and rendered) must put its input, clear and counter within 0.5px of Play's boxes (`export-parity.browser.test.mjs`).
- Pixel diff is informational: the share of pixels that differ on a 5x5 blurred luminance is written per pair under a loose 8% ceiling. The residual is the rasterizer's, not a parity claim: DOM text is drawn with LCD subpixel anti-aliasing and canvas text in grey-scale, and rounded corners anti-alias differently. Do not change product text rendering to chase it.
- Pair images: `npm run test:browser --workspace @midas/studio` writes `.artifacts/pair-<template>-<size>-<state>-{canvas,play,diff}.png`, `.artifacts/strict-parity.json` (per pair: the rows, the diff counts and the outline edges) and `.artifacts/export-parity.json` (per state: the exported and Play boxes). `.artifacts/` is not committed; regenerate by running the suite.
- Setup: after pulling a migration (apps/server/drizzle), run `npm run db:migrate`. The server refuses to start while migrations are pending and names them; a database that lacks `0008_library_docs` made `GET /api/libraries` fail with `column libraries.docs_public does not exist` (500).
- Dev needs `infra:up` with Docker Desktop running before `dev:server`, else the seed fails with ECONNREFUSED on postgres (5433); on Windows run `dev:server` and `dev:studio` separately.
- Icon Button (`icon-button`; `scripts/icon-button-model.mjs`): one managed icon slot flagged `alwaysVisible` (no switch, not optional, counts as the template's required content), no text. Variant and Color are Button's (the same modes, tokens and roles, so the Behavior panel is Button's: Variant, Color, Size), Type default|float (its own collection, visual only: the shadow token), Shape square|circle (its own collection, `shapeRadius`), Size; the box is `display.root.size: 'height'`; the radius is the Shape token (`radius-full` = Semantic/borderRadiusFull 9999, or the Size radius by alias) and every surface clamps it to half the box; float is a shadow token, never a position. Registered in the registry only: no Assets button, masters come from the later Generate Design System bundle.
- Effect tokens: kind `effect` is an `effect` variable (drop/inner shadows, an empty list is none), display property `shadow` writes `box-shadow` and the node `effects` variable. The base data holds Primitives `shadow/none` and `shadow/secondary` and Semantic `boxShadowNone` and `boxShadowSecondary`, declared in the `Effects` section of `ant-map.json`, which `buildBasePlan` emits last (Primitives, then the Semantic aliases), so `build-base-snapshot.js` writes them and a rebuild keeps them. The token JSON is not in the repo, so the rebuild is tested on the mapping's part (`snapshot-effects.test.js`), not end to end.
- The engine asks the template, not the master's layers: a template with no text slot plans its managed slots against the root (`hasTextSlot`), orders sided parts against the root, and Play draws its frame parts after its slots; a component is written under `componentNameOf(template)` ("Icon Button" is IconButton).
- `sampleProps` (schema, validated by `sampleProblems`): literal props a generated master and its demo instance start with (Input: placeholder "Input placeholder", so the master shows it); a template without it builds as before.
- Conditional containers (a managed frame slot with `shownWhen`, never `optional`; Switch's inner text boxes): the master holds it only while the condition holds at the sample props, the instance holds it as a slot-marked frame with its text inside; the plan, the export, Play and the backstop all include it exactly while its condition holds, and part-missing plus the design-system masters/demos tests exempt one that is off. `managedLayersOf`/`containerOf` and the backstop descend into slot-marked frame containers only, never into an icon slot's nested instance.
- Play toggle clicks glide the moved child with FLIP (`flipToggle`, 200ms ease-in-out, skipped under reduced motion): copy DOM children into an array first, an HTMLCollection has no map.
- A click-blocking prop hides the interaction (preview) states only, like disabled does: a persistent attribute state it carries (a loading Switch that is checked) still applies, as the canvas binds it; hover and focus keep the `[data-blocked]` guard.
- The replay harness normalises midas.js to LF before slicing functions: the file is CRLF on disk and the slicer matches LF-only boundaries.
- Input `kind` (text | password | textarea, as antd Input, Input.Password, Input.TextArea; Password and TextArea are not templates; InputNumber is its own, built with `inputFamily()` over `input-base.js`): a prop that applies to one kind is `visibleIf` that kind (a hidden prop resolves to its default), the kind writes the root `layout` and the value/placeholder `heightSizing` (`nodes` + `values` on a prop), a glyph may be shown by an enum option (`enumAttrOf`), a `marker` persistent state only says a data attribute and swaps tokens (never the instance's state), a `derived` prop may be a `{ when }` condition and never shows in the panel. The root maps `minHeight` (the Size height is a floor, the box hugs); the Input reads antd's paddingBlock (`input-padding-y-*`) so a wrapped text has its inset. The text area: value/placeholder fill the box (the whole box is the field: `data-field-box`, text cursor, `forwardFocus`), min/max height of the text layers = rows x line height (`rowsBounds`, written in `applyLiteralFields`), the footer holds the count, and the resize grip is a corner glyph (`corner: 'bottom-right'` with `inset: 'glyphInset'` (Semantic/glyphInset, 2px): the canvas's Position Absolute + right/bottom constraints, placed by `placePinned` -> `pinnedFrame` from the box and the layer's tokens on the master and every instance, never from the layer's own unapplied w/h; CSS right/bottom of the inset minus the border width; drag: `startResizeDrag`, the field's own computed min/max). The eyes take `hoverFill` on hover (Play and the export only). InputNumber: the handler column is a container pinned to the right edge (`edge: 'right'`, fixed in both axes, placed by `pinnedFrame`, out of the flow so the control is as tall as an Input; the root's end padding keeps the text clear of it and the derived `noStepper` marker state hands it back) holding two half containers (containers nest one level) with a chevron each, one-sided strokes (`strokeSides`) for the dividers, `press` on the halves with `hoverFill`/`activeFill`/`blockedBy`, `reveal` (0.2s ease, slide 100% from the right plus opacity, clipped by the control, no slide under reduced motion) on hover/focus in Play and the export only, `commitNumber`/`blurNumber` on blur. An instance made by cloning a master keeps its managed container's marker (`markManagedContainers`) and starts with the template's `sampleProps`. Solar glyph paths live in `solar-glyphs.js` (CC BY 4.0).
- Input family (`inputFamily()` in `templates/input-family.js` = the base Input minus what it drops plus what it adds, never a copy; the clear icon is out of scope for InputNumber). Pressable glyphs: a built-in glyph (eye, eyeOff, chevronUp, chevronDown) is a managed layer shown by on/off state conditions (`glyphTests`); `press: [{ slot, toggle | step }]` makes a click flip a state attribute or step the number (`prototype/press.js`, Play only; the export reports `on<Prop>Change` / `onStep`). `control.maskUnless` masks the canvas value as bullets and the input as `type=password`; `control.multiline` (TextArea) is a textarea whose box is at least rows x line height + padding (`rowsBounds`: the canvas root's minH/maxH are written in `applyLiteralFields` once the layers are bound; Play and the export use custom properties + calc()). A slot inside a conditional container exists only while the container does (`holderAllows`); a derived prop (`derived: { value, limit, cmp }`, InputNumber atMin/atMax) is read from the others, never stored. The InputNumber stepper is always drawn while `controls` is on (antd shows it on hover; a hover-only layer would be a hidden one). Not verified without a browser: the canvas drawing of the new outlines, the studio hook, a real click (`apps/studio/test/inputFamilyWiring.test.js`).
- Generate Design System (Assets tab, the only template create action): one undo step that applies the base, then a master of every registered template (built-in and Custom) on the "Design System" page, in `slots.accepts` dependency order (`design-system.js`: order, existing masters, section layout; cycles are reported and ordered last), each completed by the part generator and Auto Fix, with a demo instance holding the default icon. A master already there is completed with its own binding, never rebuilt, and gets no second demo instance. Icons come first: the bundle creates the icons of `ICON_SET` (`icon-set.js`: a name, a role and a vector path, one per role the schemas ask for; every icon slot takes the file's default icon, the first component named `Icon/<name>`, nested or not) in an Icons section before the templates, never touching an icon that exists or replacing a default icon the file has. A template that needs an icon of its own adds it to `ICON_SET`.
- Box fills sit under the border: a stroked root or box uses `background-clip: border-box` (padding-box left a hairline seam at rounded corners). A root with no stroke gets `border: 0` (a button) and, with no template `outline`, `outline: none`. Play bounds a non-instance frame by its own `minW`/`maxW`/`minH`/`maxH` (a Switch master keeps its track width); an instance reads them from its class. A toggle click glides each moved child in one FLIP (`flipToggle`: position and width together, its own width transition suspended while the end layout is measured), so a pressed Switch handle does not shrink in place before it travels; client rects are divided by the Play stage scale, which is a CSS scale). The Switch handle shadow is the effect variable `handle-shadow` (antd handleShadow: Primitives `shadow/handle`, Semantic `boxShadowHandle`, in the Size collection, bound to the handle's `effects`). The Switch press grows the handle 30% (`motion.press.growRatio`, antd switchHandleActiveInset -30%), not a fixed px. Checkbox/Radio/Switch motion follows antd-ref values (box ease 0.3s/0.2s, check easeOutBack, track ease).

- High-zoom rasters (`atlasPacker.js`, pure and swept in `raster-sweep.test.js`): a raster layer is tiled in entries of at most `MAX_TILE_TEXELS` (480, so four fit across an atlas page), margin `edgePadding` (2 texels), rastered ahead within `rasterMargin` (100 screen px from 100% up); every quad (shape, tile, raster root) is placed by `placeQuad`. A tiled layer shows its tiles only when all in view are ready, else its coarse entry; a full atlas is emptied at the next frame (`beginFrame`), never mid-frame. Open: a layer covering the whole screen at more than ~4.5 Mpx of device pixels needs more than the atlas holds (no direct-vector draw yet), and raster roots (blur/glass) are one untiled entry scaled down to the atlas. Not verified in a browser.
- Colour presets (`templates/color-presets.js`): eight Color modes, one per base Primitives palette (primary, secondary, tertiary, info, danger, warning, success, neutral); each use (subtle 50, border 200, solid 500, text 600) is a `preset-<id>-<use>` role in roles.json (32 entries) that derives a Semantic alias to its palette step. No hue presets; a new palette is added to Primitives first, then a preset may name it.
- Overflow text: `text.overflow: { value, limit }` on a text slot derives `<limit>+` above the limit (`overflowLabel`), in canvas, Play and export; never stored.
- Hiding state: a persistent state with `hide: true` (an attribute state) hides the root in Play and the export (display none, from the stylesheet); the canvas keeps the node. A derived boolean may compare with a literal number (`limit: 0`).
- Tag (`templates/tag.js`, id `antd-tag`): Color preset x Variant (filled | solid | outlined) with Size tag roles (`tag-height` per Size mode, xs/xl read the nearest step); the close is a managed frame (`closer`) holding a managed icon, pressed with a dismiss; the label is a managed text shown while non-empty. Its icon defs need a disabled colour token, so the icons take `fg` (Tag has no disabled state).
- Hover rule: every clickable icon or button-like part needs a hover state, a bound colour token (Play and the export only, the canvas stays static; disabled does not hover; any transition respects prefers-reduced-motion). Tag closer is the first (`close` icon: `hoverColour` `color-solid`).
- Badge (`templates/badge.js`, id `antd-badge`: `badge` is the studio's own `.badge` class): `type` count | dot | status; `zeroHidden` (a hiding state) holds while a zero count is not shown. It declares no disabled state (a non-interactive element: no disabled attribute, rule or guard). No motion: the count zoom-in needs a value-change animation with no layer, and the processing ripple needs an extra layer; both skipped.
- Badge corner count (a badge wrapping another element): not built. To add it later: a wrapper template with a `children` frame slot, the Badge as a managed frame pinned to the corner (`pinnedFrame`, sized from its tokens), and its count as the overflow text.
- Dismiss press (`press: [{ slot, dismiss: true }]`, one action per press): Play marks the root dismissed and runs `motion.exit` (fade and scale, 0.2s), hidden at once under reduced motion; the export calls `onClose` and hides through local state; the canvas is static; a disabled element does not dismiss. Tag (not yet registered) uses it.
- `element.disabledState` is optional: without it the export, Play and the stylesheet write no disabled attribute, rule or guard. Ids: `avatar` and `badge` collide with the studio chrome (`.avatar`, `.badge` in styles.css); Avatar uses `antd-avatar`. `tag`, `divider` and `typography` have no collision.
- Play draws a managed text layer with its slot class (`<template>-<slot>`, as the export) and leaves its bound typography to the stylesheet; a template's instance layers get plain ids.
- Locked for Batch 2a (partly implemented; Tag, Badge and Divider are registered): Tag and Badge colour presets: the eight base palettes (primary, secondary, tertiary, info, danger, warning, success, neutral); no hue presets. Typography: generic `fontStyle` and `textDecoration` fields, underline and delete composed into one value; code and mark style the root frame (token fill, padding, radius, border) with no extra layers. Avatar: image content via a generic image-fill prop on the frame, last.

- Divider (`templates/divider.js`, id `antd-divider`): every rule is a managed vector line node (anatomy `kind: 'line'`, `axis`, optional `fill`; made by `managedLineLayer`, bound by display `stroke`/`strokeWidth`/`width`/`height`), never a thin frame: line nodes are raster layers by design (`midas.js` `raster`), so `dividerRaster.test.js` holds them to the tile budget and the atlas. Layers: line, text, line (horizontal) or one vertical line; a short side (placement start/end) is its own slot with a width token, the other fills; hasText/vertical add and remove them, nothing hidden. The Style variable (`styles` dashed/dotted) is written on the root and on every managed line layer (`applyVariantStroke`; a sync that makes a line writes it on that layer alone); dotted is `variantStrokePatch`: dash 0, gap 3, round cap. A persistent marker state may swap a typography token (`derivedNodeProps`); `plain` does. Size sets only the root's padding above and below (the same in vertical). Open: codegen and Play have no line emitter, so the export reports `unsupported-slot` and Play draws no Divider; the canvas layout of a zero-height line in auto layout is not verified in a browser.
- Password eye toggle without props, unblocked by a generic engine addition: a press may flip a local interaction state (`press.toggleState`, root `data-<state>`, Play flips it, the export keeps it in `useState`), an icon def may swap by that state (`swap: { by, is }`: a prop-only def takes no canvas layer via `planAnatomy`, Play draws it from its component, the export gates both sides in JSX with matching stylesheet rules), and `control.maskUnless` may name the local state. Input password uses it (`revealed`): the canvas holds the eyeOff layer alone, eyeOn is prop-only, both pickers show for kind password (`Icon eyeOn` / `Icon eyeOff` labels); no `visibilityToggle` / `passwordVisible` anywhere. Swap icons: the prop-only icon is drawn in Play as a positioned wrapper of the slot class holding ONE svg of the component frame (viewBox = frame, 100%, uniform; `frameSvg`); the stylesheet writes only the hidden side (`display: none !important`, since a nested icon carries an inline display). Icon glyphs (`iconNodes`) are the tight box of the path, absolute in the auto layout frame with Scale constraints: an instance sized to the slot scales them by `constrainInstanceLayers` (uniform only because the icon frame is square). The tight-bounds core is `geometry/vector-bounds.js`. Not verified in a browser: that the studio runs the constraint pass when the slot size binds.

## Known issues

- The Behavior panel's Text|Icon segmented control and the Input prefix/suffix rows are covered by unit tests only; they have not been looked at in a browser. `affix.browser.test.mjs` was edited to the new rows and not run.

- Strict parity (browser) fails 3 of ~100 Input xs pairs, on HEAD and since: `xs allowClear` and `xs showCount` "outline not found on both shots" and `xs suffix` outline 0.70px. The part boxes match within 0.01px, so it is the outline edge check on a 16px control, not layout. Part 2 (single border) could not re-verify without a browser; presumed unchanged. 2026-11-04: two consecutive full browser runs (before and after the export text-part fill fix) show all 50 strict pairs green including every xs pair, so the 3 failures did not reproduce; kept for one more run before deleting.
- The browser harness reuses any server already listening on 4000/5174, so a stale `test:browser` run (or its servers) shares the database with the next run and makes it flaky (timeouts, a "changed somewhere else" dialog). Stop stale runs before a baseline. Browser DevTools unchecking a declaration comments it out in the style attribute and is not a product bug.

- Fase 0 browser verification (canvas, Play, codegen in a real React project) not done — no browser automation.
- The roadmap names `strokeStrategyOf`/`rootLayoutOf`/`labelLayoutOf` and a `both` placement: none exist in code; if wanted, they are new features, not fixes.
- Wave colour is the variant's strong colour (solid bg, outlined/dashed border, filled and text fg); the spinner is antd's quarter arc (LoadingOutlined geometry, 1.5px stroke, sweep 25%), and a part with `spin` turns in Play only (the codegen export draws the arc at rest, sized by its display `size` token; a width set by hand on the part layer wins over the template default everywhere, like any user stroke style).
- Single border element: each Button/Input root draws its border and carries its fill on the host itself, in Play and export (no `::before`, no fill-clip layer); the corner halo risk is accepted. Unbound custom dash/gap, or a round/square cap, uses an SVG overlay, and then the host draws none. An absent gap follows the dash; clearing Gap deletes the key.
- Border width is a variable: the Button/Input root stroke binds `strokeWidth` to `border-width` (`Semantic/lineWidth`, 1), so the designer changes it through the variables, never a literal; the focus ring derives from `outline-width` (`Semantic/controlOutlineWidth`, 2).
- Outline/ring/wave: `outline-color` is always 0% at rest (alias to Semantic `outlineTransparent`, itself a 0% Primitive derive); `outline-color-active` is the interaction colour. The outline width includes the border: the ring starts back at the border's inner edge (an inside stroke), so the visible ring is width minus border with no gap (the `outline-width` token, `outline: { offset: 0 }`, the engine emits `outline-offset: -border` from the resolved binding, `outline: none` when the border spans the width, `outline-swallowed` warns); never drawn on canvas (the canvas preview only recolors fill/stroke), no panel controls. Ring (`:focus-visible`) and wave (click, `data-wave-on`) are DOM-only behaviors configured by schema `interaction`.

- `icon-button-wave` pinned Input hash is stale at HEAD (actual `595275bc2b1258a3` vs pinned `83551c0642aa0803`); fails on a clean tree, needs a diff-then-repin pass.

## UI conventions

- Reuse the shared panel primitives (the classes in `apps/studio/src/styles.css`: `inspector-section`, `section-heading`, `cmp-props` / `cmp-prop2` / `cmp-ctl`, `cmp-input`, `vsw`, `empty-state`, `small-label`, `badge`). Do not write one-off styles for a panel.
- Spacing, sizes and typography come from the shared classes and tokens in `styles.css`. Do not add literal values to a panel's markup.
- No browser-default list styling. Do not use `<ul>` or `<li>` in a panel; use label rows.
- One title per panel. The tab names the panel; section headers use the `section-heading` style.
- Every prop is a label beside its control (`cmp-prop2`), the same as the Design panel's instance props.
- Any UI change is verified visually: take a screenshot of the changed state next to the Design panel for the same selection before reporting it done.
